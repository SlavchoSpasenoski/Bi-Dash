# Bi-Dash QA campaign — 2026-11-22

## Scope and isolation

User requested rigorous functional and security testing, followed by fixes for confirmed errors. Tests use disposable PostgreSQL/Redis and synthetic MySQL/MariaDB data. Destructive BaseTestCase fixtures never target the installed metadata database. No business SQL, real invitations, paid provider calls or Contabo changes are part of this campaign.

## Confirmed findings and repairs

| Priority | Finding | Repair / regression evidence |
| --- | --- | --- |
| P1 | Organization Admin implicitly inherited installation-wide diagnostics and could add privileged memberships or manage an instance administrator's account. | Require explicit same-org instance capability; protect privileged accounts, credentials and group mutations. Positive instance-admin and negative org-admin tests cover diagnostics, key disclosure, invitations, password reset, role/group changes and disabling. Report editing remains allowed for any same-org Admin. |
| P1 | Group member lookup could reveal another organization's users. | Resolve the group within the current organization and scope returned members. Corrupt cross-org group IDs no longer confer permissions or appear in group lists. |
| P1 | Alert subscription deletion trusted a global subscription ID, allowing cross-org or mismatched-alert deletion. | Resolve the local alert and match both subscription and alert IDs before ownership/admin checks. |
| P2 | Session restoration accepted forged completion messages; changing login account could replay an old request with stale identity. | Require exact origin and popup source; compare original/restored actor. A changed or missing actor rejects replay and reloads the session. Same-actor restoration preserves the workflow. This was not a demonstrated backend authentication bypass. |
| P2 | Help iframe messages accepted lookalike origins and an unrelated message source. | Validate URL protocol, exact origin and owning iframe source; update only the intended Help link. |
| P2 | Monitoring retained cached identities/jobs after HTTP 401/403. | Clear privileged snapshots on authorization denial; transient failures retain explicitly stale state. |
| P2 | Imported query hash differed from normal execution hashing, leaving report result pointers unpopulated until another Save. | Match runner normalization, parameter defaults and auto-limit behavior without executing sources or loading dropdown results during migration. A real PostgreSQL/RQ test passes; restoring the old hash calculation makes that test fail. |
| P2 | Malformed package descriptions/history/integer fields could pass preview and fail during import. | Validate nullable text, history definitions, IDs and integer bounds before writes; regression cases verify client errors and rollback. |
| P2 | One inaccessible alert caused the entire alert list to fail; organization counters counted hidden reports. | Filter readable alerts before serialization; use central dashboard/query visibility for counters. |
| P2 | Saved View only execution was accepted by the HTTP path but denied by the worker; source definition editing could undermine the distinction. | At the user's explicit decision, Editors may execute accessible saved queries with safe declared parameters. Revalidate the saved SQL and parameters at enqueue/worker time; Full source access is required for definition edits/ad hoc work. Protected execution preserves column rules. Actual PostgreSQL and MySQL worker tests pass. |
| P2 | Malformed email values caused server exceptions in profile/invitation validation. | Reject invalid shapes/types with HTTP 400. |
| P3 | Hiding a tab while its heartbeat was in flight could drop the idle transition. | Queue the idle update after the pending heartbeat. |

## Test-contract corrections

Historical tests still expected public object-token access, collaborator editing of other Editors' queries, automatic dashboard sharing through source groups, orphan cached-result access, or anonymous worker execution. Fixtures/assertions now enforce the agreed Bi-Dash contracts. Cached-result tests supply actual worker-style provenance instead of bypassing the result guard. A foreign group-list fixture now verifies exclusion rather than expecting disclosure.

The broad model runner exposed test cleanup using Redis FLUSHALL; it now uses FLUSHDB. A pre-existing pytest-only skip for unsupported email search parsing is expressed with unittest.skip so both runners respect it. No new product failure was hidden with a skip. Frontend ScheduleDialog failures in the first run were caused by using the wrong test timezone; the final run uses the configured Africa/Khartoum timezone.

## Limits

This is a bounded local campaign, not a proof that every connector or deployment has no vulnerabilities. External provider integrations, every optional data-source driver and sustained production load were not exercised. The broad campaign used disposable local resources; the later Contabo build, additive migration and authenticated/public smoke checks are recorded separately in STATUS.md. Destructive test fixtures were never run against live metadata. Existing instance administrators remain trusted operators with global diagnostic access. Telemetry remains approximate and bounded as documented in SYSTEM_MONITORING.md. Nonblocking upstream React/SQLAlchemy deprecation and frontend source-map warnings are separate from failed assertions.
