Views, system schemas, arbitrary functions, session variables, output files, multiple statements, comments/hints and ambiguous lexer constructs are denied. Unsupported ordinary SQL may need rewriting.
- The shared account may have full server privileges. Bi-Dash enforces SELECT-only execution with fixed SQL mode, disabled LOCAL INFILE/multiple statements and native/socket/lock timeouts. This boundary does not restrict a person directly using the DB credentials. Database/application administrators are trusted.
- Editor query/result/export/cache/job scopes derive from normalized effective rules and keyed connection identity. Broad Reader/admin caches cannot be reused by Editors. Scope changes invalidate old Editor queries/results; recreate them under the intended scope. Unrelated rule saves preserve unchanged effective scopes.
- Reader cached report/export access uses existing source-group and download permissions, not Editor column rules; SQL/tokens remain redacted. Readers cannot submit arbitrary SQL, even with accidental execute permission. They may refresh saved dashboard reports with safe typed parameters through the dedicated authorized MySQL/MariaDB/PostgreSQL path. No per-Reader dashboard ACL has been added.
- Protected schedules/alerts/public tokens remain unavailable. Editor query dropdown dependencies are unavailable; Readers may use authorized cached dropdowns. AI and derived-source execution restrictions remain; Reader authorized cached derived results retain dependency-group checks.
- Removing all rules leaves source protection in place and denies Editors without rules. Retired private IDs and old profile credentials never become fallback routes.
- Row filtering, masking, scalable bulk schema selection/pagination, wider SQL compatibility and additional adapters remain future work.
